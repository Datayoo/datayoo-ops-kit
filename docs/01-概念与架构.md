# 01 概念与架构

## 算子是什么

算子是数据处理流程中可复用的处理单元：有明确的输入、输出与可配置参数，在流程中被编排、执行。

本规范只谈如何把算子对接到 HuggingFists；业务含义由开发者自己定义。

## 定义态与实现态

每个算子通常包含两层，导入平台时也按这两层交付：

| 层次 | 作用 | 说明 |
|------|------|------|
| **定义态（Descriptor）** | 描述「这是什么算子、怎么配」 | 名称、参数、输入输出结构、参数校验，以及参数在页面上如何呈现等。`@OpDefiner` 字段见 [OpDefiner注解说明](OpDefiner注解说明.md)。 |
| **实现态** | 描述「真正怎么跑」 | 算子的实际执行逻辑；也可按需补充面向特定计算框架的参数。写法见 [03 实现态](03-实现态.md)。 |

**参数怎么来：** 以 Descriptor 侧的配置为基线。实现态**可以不配参数**，此时直接沿用 Descriptor；若实现态也配置了参数，则与 Descriptor **合并**（不同计算框架下参数可能不同，因此允许实现态增量声明）。名称、行为等仍应对齐用户可理解的语义；参数本身不是「两边必须写成同一套」。

用户导入时通常需要两层对应产物都就绪，才能在流程里配置并跑起来。

## 执行引擎：Oyez、Gosooz、Moz

实现态跑在平台的计算引擎上。三套引擎分别叫 **Oyez（欧冶子）**、**Gosooz（公输子）**、**Moz（墨子）**——取墨家脉络里几位与「造物、技艺」绑在一起的名字，对应三类计算框架：

| 引擎 |  计算框架 |
|------|----------|
| **Oyez** | 单机 |
| **Gosooz** | Spark |
| **Moz** | Flink |

自研算子**只开放 Oyez（单机）**。Gosooz、Moz 为平台侧能力，不在自研开放范围内。实现态写法见 [03 实现态](03-实现态.md)。

## 算子与其它概念的边界

| 概念 | 与算子的关系 |
|------|----------------|
| **连接器** | **不是算子**。连接器负责对接外部系统，当前包括数据库、文件系统、消息队列等。开发与导入路径与算子不同（资源库中的连接器库）。 |
| **流程** | 编排与运行算子（以及其它节点）的载体。算子导入后，在流程中作为可配置、可执行的节点使用。 |
| **脚本 / Prompt / 小工具** | **与本规范无关**。自研算子扩展不覆盖这些对象。 |

## 官方分组

算子在库中按分组展示。挂靠某一分组时，tag 配成 `name` 路径（如 `input,db`）。完整对照见 [官方算子分组](官方算子分组.md)。
