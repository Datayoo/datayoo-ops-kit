# 00 原则与范围

## 定位

给**自行开发算子**的用户看的对接说明：怎样按 HuggingFists 的扩展方式，把算子做出来、打成可导入包、装进平台自己用。  
不是平台运维手册，也不是对客户代码的管理制度。

## 读者

需要在 HuggingFists 上扩展数据处理能力、自己开发并导入算子的人。

## 管什么 / 不管什么

| 管（对接所需） | 不管（你自己的事） |
|----------------|---------------------|
| 算子在平台中的概念与分层 | 业务逻辑对不对 |
| 开发 → 打包 → 导入的推荐路径 | 内部排期、归属、Code Review |
| 要能被平台识别并导入时，交付物应具备的能力 | 自研算子上线后的运维与值班 |
| 使用平台扩展时的常见注意点（建议） | 替你保证安全、合规、无漏洞 |

## 几条实用建议

| 建议 | 含义 |
|------|------|
| 可被平台导入 | 按约定打出平台能识别的包 |
| 描述与行为对得上 | 界面配置与真实执行一致；参数以 Descriptor 为基线，实现态可增量合并 |
| 变更可替换 | 升级时想清楚对已有流程的影响 |
| 包内不落密钥 | 密钥进包会泄露 |

## 成功标准

按规范走通后：算子能打包、能导入、能在自己的流程里跑起来。
